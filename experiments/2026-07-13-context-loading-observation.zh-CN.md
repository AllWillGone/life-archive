# 上下文读取策略：探索性观察

[English](2026-07-13-context-loading-observation.md)

证据等级：**探索性观察**

日期：2026-07-13

公开 LifeArchive commit 或发布版本：未记录

## 观察问题

当启动提示词让模型自行判断需要读取多少 LifeArchive 上下文时，不同测试环境中的模型配置表现有何差异？

本次记录只观察上下文覆盖范围和大致窗口占用，没有评估记忆检索准确性、回答质量或长期维护质量。

## 已记录条件

| 字段 | 已记录内容 |
| --- | --- |
| 上下文窗口 | `256k`；原始记录没有保留单位，也没有说明这是配置值还是模型上限 |
| 记忆库 | 一个私人 LifeArchive 实例；不公开私人夹具、提示词输出、文件名或记忆内容 |
| 提示词对照 | 基线策略，以及让模型自行判断读取量的修改后策略 |
| 模型标签 | 从测试环境抄录的本地显示标签；没有保留规范模型 ID 或标签来源 |
| 运行次数 | 未记录 |
| 测量方式 | 大致上下文窗口占用；没有记录测量工具和统计边界 |

下表标签不能被解释为已经核验的公开产品名称，其中可能包含本地别名或推理配置。

## 观察结果

| 环境标签 | 上下文读取策略 | 观察到的文件覆盖 | 读取完成后的大致占用 |
| --- | --- | --- | --- |
| `5.5 xhigh` | 基线策略；不让模型自由决定读取范围 | 没有记录具体文件覆盖 | 约 50% |
| `5.5 xhigh` | 修改后提示词；由模型自行判断读取多少 | 占用有所下降，但没有记录具体文件覆盖 | 约 40%-45% |
| `5.6 terra` | 由模型自行判断读取多少 | 读取整体文件列表和最近或最相关的 1-2 个事实文件，其余内容很少读取 | 约 10%-15% |
| `sol` | 由模型自行判断读取多少 | 读取整体文件列表和最近或最相关的 1-2 个事实文件，其余内容很少读取 | 约 10%-15% |

## 解释

在已记录条件下，同一种“自行判断读取范围”的指令，在不同环境标签下产生了明显不同的启动行为。

对 `5.5 xhigh`，修改后的提示词对应较低的估算占用。对 `5.6 terra` 和 `sol`，占用明显更低，但观察到的文件覆盖也很窄。因此，较低占用本身不能证明上下文构建更有效。

这项观察支持 LifeArchive 当前使用明确路由步骤：先读取当前状态和索引，再在任务需要时打开相关底层文件。它不能证明某个模型或配置普遍优于其他模型或配置。

## 局限

- 没有保留基线和修改后提示词的完整文本。
- 没有记录记忆库快照、初始上下文、客户端版本、工具配置和重置流程。
- 没有记录对应的公开 LifeArchive commit 或发布版本。
- 没有记录运行次数和不同运行之间的方差。
- 窗口占用只是估算值，不清楚是否包含系统提示、工具输出和启动前上下文。
- 文件覆盖只做了定性描述，没有保存完整读取轨迹。
- 没有测量任务正确性、召回率、引用准确性或回答质量。
- 模型标签不是规范标识。

因此，这些结果只能作为历史观察，不能支持因果结论、模型排名或可复现基准。

## 建议复现方式

使用版本化的合成记忆库，完整保留两组提示词，在条件允许时记录规范环境标识，每次运行前重置上下文，并捕获全部文件读取轨迹。指标应同时覆盖成本和有效性，例如输入 token、打开文件数、相关事件召回、无依据陈述、链接准确性和回答质量。
