# 公开模板安全说明

[English](public-template-safety.md) | 简体中文

只有当 LifeArchive 仅包含规则、空结构、合成或彻底脱敏的示例，以及经过审阅的研究材料时，才适合公开。实际使用中的自传式记忆库通常应保持私有。

## 首次使用前

- 建立新的私人目录或私有仓库，不要在仍连接公开模板远端的 clone 或 fork 中填写记忆。
- 如果使用 Git，写入个人内容前运行 `git remote -v`，并确认仓库可见性。
- 明确决定是否让 Git 版本化私人记录。模板 `.gitignore` 会排除部分新建底层文件，但已经被 Git 跟踪的文件在编辑后仍可被提交。
- 只授予必要的文件系统和 AI 服务访问权限，并检查相关服务的数据保留和训练设置。
- 根据记忆库的敏感程度使用加密存储或备份。私有仓库提供的是访问控制，不等于加密。
- 不在记忆库中保存密码、API key、访问令牌、私钥、助记词、恢复码、完整金融账户或完整证件号码。

## 可能识别个人的信息

同时检查正文和元数据中的：

- 真实姓名、别名、用户名、邮箱、电话号码和账户标识；
- 地点、单位、学校、日期、关系细节、健康信息、亲密经历和罕见事件组合；
- `people/`、`fact/`、`feeling/`、`session/` 和 `inbox/` 下的文件名；
- 即使没有详细事件，也可能泄露敏感信息的摘要和索引；
- 原始聊天、模型输出、截图、附件、导出日志和私人绝对路径；
- commit 作者姓名与邮箱、提交信息、分支、标签、stash、远端，以及仍保留在 Git 历史中的已删除内容；
- 云同步副本、备份、缓存和曾经公开的 fork。

如果其余细节组合仍能重新识别个人，仅替换姓名并不构成充分脱敏。

## 公开发布前

1. 从从未包含私人记忆的干净副本或新仓库发布。只从最新提交删除文件不会清除 Git 历史。
2. 使用明确的公开文件允许列表，不复制私人 `fact/`、`feeling/`、`people/`、`summary/`、`session/`、`inbox/`、附件或私有仓库历史。
3. 用合成材料替换示例和实验夹具，逐行清理提示词与模型输出；不能因为文件位于某个公开目录就视为安全。
4. 检查文件名、`git status`、暂存区、已跟踪文件、链接、commit 元数据、分支、标签和仓库历史。
5. 扫描认证秘密和直接标识符，再人工审阅自动扫描难以发现的间接标识符和特殊组合。
6. 当源材料较敏感时，让第二位审阅者检查待发布内容。

`.gitignore` 只能作为纵深防护，不能隐藏已跟踪文件、清除历史、加密数据，也不能阻止显式强制添加。

如果私人材料或认证秘密已经公开，应视为已经泄露：立即撤销或轮换认证信息，限制仓库访问，并按托管平台流程清理历史。即使完成清理，副本和缓存仍可能继续存在。
