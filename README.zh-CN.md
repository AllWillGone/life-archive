# LifeArchive

[English](README.md) | 简体中文

一个用于 AI 辅助长期回顾的自传式记忆系统。

LifeArchive 是用于维护私人记忆库的公开模板，可以长期记录经历、关系、情绪变化和未解决线索。它把可观察事件、使用者的感受与理解、导航摘要和用户原话分层保存，让 AI assistant 能按需恢复上下文，而不是把一生压缩成单一人物画像。

本仓库只包含可复用的规则与审计工具、空结构、模板、合成示例和经过清理的研究记录，不得包含任何人的真实记忆库或其 Git 历史。

## 核心模型

- `fact/` 记录发生了什么，并保留来源和不确定性。
- `feeling/` 记录使用者如何感受、理解、反应和变化。
- `summary/`、索引和 `people/` 是轻量路由层，不是底层记录的重复副本。
- `session/` 按日期和发言顺序保存普通自传式对话中的用户消息全文，保留原始措辞、段落和消息边界，供核对、补记和重新整理使用；不生成记忆更新摘要，也不保存 agent 回复、建议、分析或文件清单。旧版摘要保留原样。
- `inbox/` 是无法安全归档内容的最后缓冲，不是主要记录线索。
- `experiments/` 保存系统研究，不属于自传式记忆。

底层原则很简单：忠实保留使用者的记忆，不把它改写得更整洁、更体面或比来源所支持的程度更加确定。

## 仓库结构

```text
LifeArchive/
  AGENTS.md                 # 权威维护规则
  README.md                 # 英文项目指南
  README.zh-CN.md           # 简体中文项目指南
  CHANGELOG.md              # 公开模板版本记录
  docs/
    templates/              # 空白记忆文件模板
    public-template-safety.md
    public-template-safety.zh-CN.md
  examples/                 # 只放合成示例
  experiments/              # 系统设计观察与实验
  maintenance/              # 通用审计协议；生成状态保持私有
  summary/                  # 总览、当前状态、时间线、人物、主题
  people/                   # 可选人物路由卡片
  fact/
    index.md
    events/                 # 按事件记录的事实
  feeling/
    index.md
    by_event/               # 与事件关联的情绪记录
  session/                  # 按日期保存用户原话，保留消息边界
  inbox/                    # 未解决碎片
  archive/                  # 仅保存旧格式和迁移备份
```

普通对话从当前状态和索引开始，再按需打开相关底层文件；不会默认读取全部事件、人物卡或实验。完整读写规则见 `AGENTS.md`。

普通自传式对话不读取 `experiments/` 或 `maintenance/`。项目维护、规则讨论、系统实验和周期审计的技术内容不写入自传式记忆目录；使用者明确说本轮不记录时，也不保存原话或另写事实、情绪和摘要。只有使用者明确提出开展或继续系统实验时才读取 `experiments/`；只有明确提出启动、恢复或执行周期审计时才读取 `maintenance/`。

## 安全开始

不要直接在仍连接本公开仓库的 clone 或 fork 中填写私人记忆。填充后的仓库可能通过正文、文件名和 Git 历史暴露姓名、地点、关系和情绪记录。

1. 下载压缩包，或只复制模板中已跟踪的文件而不复制公开仓库的 `.git/` 目录，将它们放入新的私人目录或私有仓库。如果使用 Git，写入个人内容前应确认仓库可见性并运行 `git remote -v` 检查远端。
2. 只向 AI assistant 授予该私人目录的读写权限，并让它先读取根目录的 `AGENTS.md`。
3. 决定是否用 Git 版本化私人记忆。附带的 `.gitignore` 会忽略部分新建底层记录，作为有限的纵深防护；只有确认仓库为私有后，才按需要删除或调整这些规则。
4. 人工审阅重要写入，并根据内容敏感程度维护加密备份。

`.gitignore` 不是隐私边界。已经被 Git 跟踪的初始摘要和索引在填入内容后仍可被提交；私有仓库本身也不等于加密。首次使用或公开发布前，请阅读[公开模板安全说明](docs/public-template-safety.zh-CN.md)。

## 周期审计

公开模板包含通用 maintenance-5 审计引擎，供复制到私有仓库后使用。它采用“轻量审计、严格执行”模式：可以审计一篇、多篇、全部已变化文档或完整配置范围；只显示带有精确修改前后的真实建议，不铺开每份已审计文档；每项修改始终由使用者决定。

新建私有副本后先初始化一次本地基线：

```text
node maintenance/.system/audit.mjs init
```

然后使用下面的周期整理提示词。命令拒绝替换已有状态。请把 `maintenance/baseline.json`、`maintenance/run/`、`maintenance/proposal.json`、`maintenance/proposal.md`、`maintenance/proposals/`、`maintenance/reviews/`、迁移备份、锁和恢复材料保持私有，不要提交到公开仓库。

范围选择、精确审阅、自定义提议、授权和恢复流程见 [`maintenance/README.zh-CN.md`](maintenance/README.zh-CN.md)。

## 新对话启动提示词

适合普通对话。提示词只引用 `AGENTS.md`，避免复制一份会随版本漂移的规则正文。

```text
请先读取当前仓库根目录的 AGENTS.md，并按其中“启动上下文构建”和“按需深入与写入前读取”规则建立上下文，不要默认读取全部底层记忆。

之后像平常一样优先和我聊天、分析和回应，不要把自己变成记录员。按 AGENTS.md 安静将我的原话追加到 session；出现新的事实、情绪变化、关系线索或事件线索时，再维护对应的事件和必要索引。项目维护和我明确不记录的内容不保存。
```

## 周期整理提示词

适合索引、摘要、事件边界或待处理内容逐渐漂移时使用。它要求先审计，再进行任何重构。

```text
请先读取当前仓库根目录的 AGENTS.md。这次任务是周期整理，不是普通聊天；全程遵守其中的真实性、底层记忆保护、隐私和写入确认规则。

先只审计，不要修改记忆文档。如果这个私人副本还没有 `maintenance/baseline.json`，先运行一次 `node maintenance/.system/audit.mjs init`。然后运行 `node maintenance/.system/audit.mjs status` 和 `node maintenance/.system/audit.mjs validate`。有未完成 run 时按其中记录的 `next_action` 恢复；否则选择一种范围：

- 指定文档：重复使用 `--path`，或使用 `--paths-file`；需要预览依赖时先运行 `scope`；
- 已变化文档：不带 mode 运行 `start`；
- 全部文档：只有我明确要求或语义规则确有需要时才运行 `start --mode full`。

只读取每个目标及系统列出的必要只读依赖。不要把依赖自动变成写入目标，也不要把局部审计冒充全仓审计完成。

重点检查并提出方案：
1. fact、feeling 和 agent 内容是否符合 AGENTS.md 的归档边界，是否存在完整事件重复复述。
2. 事件、关系阶段和跨事件主题的边界是否合理，是否存在重复或过碎记录；不要仅因文件较长拆分连贯阶段。
3. 两个 index、总时间线和事件内时间线是否符合排序规则，“最近更新”是否滞后。
4. current、overview、人物卡和主题索引是否仍履行路由与派生职责，是否保存了重复或唯一细节。
5. inbox 和 session 是否仍符合各自职责。
6. 链接、纯文本路径、文件名、日期精度和 UTF-8 是否一致。文件创建后优先保持路径稳定；只有文件名明显错误、重复或不利检索时才提出重命名方案，并在确认后同步所有引用。

用 `checkpoint` 保存已完成或部分完成的单元，再发布经过核对的提议草稿。默认人类视图必须先显示操作索引，再只展开真正的建议；每项显示精确的修改前、修改后和少量上下文，不要铺开所有已审计文档全文。

允许我通过 `revise` 新增、删除、替换操作或更换目标。只有我明确给出提议编号、版本和操作编号后，才能执行 `decision` 或 `apply`。只有 `apply` 可以修改记忆文档；如果目标、必要依赖或语义策略发生漂移，必须在任何写入前停止整批操作。完成后只汇报实际成功的写入，任何失败或不确定都要明确指出。准确命令和 JSON 格式见 `maintenance/README.zh-CN.md`。
```

## 阶段性摘要瘦身提示词

适合：`summary/current.md` 逐渐变成长篇近期记录，导致新对话启动上下文过大，或者未来 agent 容易被已经过期的近期细节带偏时使用。

不适合：不用于重建总时间线、新建人物卡、调整底层事件结构、全面整理其他摘要文件，或评估个人 review 等新结构。

```text
请先完整读取当前仓库根目录的 AGENTS.md。本次任务是“summary/current.md 阶段性瘦身”，不是完整周期整理，也不是普通聊天。

本轮只授权只读审计。不得创建、修改、移动、重命名、删除或格式化任何文件，也不得更新“最近更新”、索引、链接、AGENTS.md、README.md 或 CHANGELOG.md。即使问题明显、修改机械、风险很低，也必须先列入审计方案。

审计可以提出推荐方案并说明理由，但不能替我作最终决定。所有压缩、移除、迁移和链接调整都必须列为候选，并说明信息承接位置、风险和预计结果。

本次唯一主要目标是把 current 从近期事件流水和分析汇总恢复为“当前状态快照”，从而显著减少新对话的启动上下文。不得为了达到固定字数或缩减比例而损失信息。

第一阶段只读审计：
1. 完整读取 summary/current.md，统计字符数、行数、条目数和各部分占用。
2. 读取 `summary/overview.md`、`fact/index.md`、`feeling/index.md`、`summary/people.md` 和 `summary/topics.md` 作为路由参考。
3. 对 current 中每条候选内容，只按需要读取直接相关的少量 fact、feeling、人物卡或 session，核验底层是否已经承接；不要默认读取全部底层记忆。
4. 无法确认底层是否承接时继续保留并标为待核验，不得仅凭摘要推断或直接删除。

一条内容只有符合至少一种情况时才继续留在 current：
- 关系、事件或目标仍在进行；
- 存在明确临近节点；
- 尚未解决的问题仍在影响近期决定或情绪；
- 近期反复出现，并且很可能继续成为后续对话入口。

仅仅最近谈过、曾经很强烈或具有长期意义，不足以留在 current。

每条活跃主线通常只保留：
- 当前结论或状态；
- 尚未解决的核心问题、使用者已经作出的明确决定或下一节点；
- 对应的 fact、feeling 或人物入口。

不保留状态形成过程的逐日更新、完整事件复述、重复背景和长篇分析。使用者明确表达且仍有效的需要、愿望和决定可以保留；agent 提出的建议、提醒和分析，除非后来被使用者明确采纳，不作为使用者当前状态保留。

从 current 移除的内容不自动迁入 timeline、overview、summary/people.md 或 topics。只有符合目标文件自身职责时才提出迁移；否则确认底层和 index 已有入口后，只把 current 中的派生副本列为移除候选。

如果某条个人内容只存在于 current，先判断它属于可确认事实、使用者明确情绪或愿望，还是 agent 分析。前两者提出底层承接方案；agent 分析不得新写入 session，旧版 session 中已有的分析保持原样。无法分类时继续保留并标记，不强行迁移。

默认写入候选只限 summary/current.md。overview、timeline、summary/people.md、topics、两个 index 和底层文件本轮只用于核验；如果 current 中的唯一信息必须先承接，或者瘦身会造成必要链接失效，将相关修改作为独立批次提出。不得借机重建 timeline、新建人物卡、调整事件结构或创建阶段性自我认识文件。

审计后先提交：
1. current 当前字符数、行数、条目数和主要膨胀来源；
2. 建议采用的新结构预览；
3. 保留、合并压缩、移除、待迁移和待核验的内容分类；
4. current 中的唯一信息及拟承接位置；
5. 每个拟修改位置、处理方式、理由、风险和可验证结果；
6. 预计瘦身后的字符数、条目数和缩减比例；
7. 需要我明确决定的问题。

提交审计报告后立即停止。本提示词本身不构成写入授权。只有我之后明确确认的编号批次、具体文件和具体操作才可以执行；未确认、表述不清或执行中临时发现的修改都不得顺带处理。

确认执行后，只实施获批内容。完成后报告 current 的前后字符数、行数和条目数，检查所有链接，并确认未经批准的 fact、feeling、session、人物卡和其他摘要文件没有变化。任何失败或不确定都必须明确指出。
```

## 系统实验

[实验索引](experiments/README.zh-CN.md)用于把技术研究与自传式记忆分开。公开实验只能使用合成或彻底脱敏的材料，并说明方法、测量限制、模型标签来源和证据等级。缺少控制条件的记录只能称为探索性观察，不能包装成基准测试。

### 系统实验提示词

适合：明确开展或继续 LifeArchive 的系统设计实验、提示词对照或模型行为评估时使用。

```text
本次任务明确进入 LifeArchive 系统实验模式。请先完整读取 experiments/README.zh-CN.md，再根据我指定的实验、文件名或关键词读取最相关的既有实验文件；不要默认读取全部 experiments/，也不要默认读取自传式记忆。

纯技术过程和结论只写入 experiments/。如果实验实际促成系统能力、目录职责或维护规则变化，再把已经发生的版本变化记录到 CHANGELOG.md；不要把技术实验内容写入 fact/、feeling/、summary/ 或 session/。

公开实验只使用合成或彻底脱敏的材料，发布前按公开模板安全说明核验。
```

## 局限

LifeArchive 是纯文本组织方法，不提供加密、访问控制或自动备份，也不是临床记录或专业支持的替代品。AI assistant 可能遗漏、误分类或过度解释信息，重要记录需要人工复核。
